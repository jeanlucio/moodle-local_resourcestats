# ✨ Features

* 📊 **Access Badges:** Up to five independent badges displayed below each resource on the course page, visible only to teachers: total accesses, unique students, last student who accessed, students who completed, and students who passed.
* 👤 **Unique Student Count:** Tracks how many distinct students accessed each module.
* 🔁 **Total View Count:** Tracks repeated accesses, counting every visit individually.
* 🧑 **Last Visitor:** Displays the name of the most recent student who accessed the module.
* ✅ **Completion Badges:** For activities that track completion, a badge shows how many of the students tracked for completion have met the activity's conditions, and — where completion requires a passing grade — how many passed. Which states count as completed follows core's own rule, so the figures agree with the Activity completion report: a failing grade counts as completed only where completion does not require a pass. Activities without completion tracking show no badge at all rather than a zero. Unlike the access statistics, these figures come from Moodle's own completion data, so they cover the whole history of the course, including before this plugin was installed.
* 📅 **Per-Student Statistics:** Dedicated page per module showing each student's view count, first access date, last access date, and — where the activity tracks completion — their completion state, with server-side sorting and pagination. A student the course does not track for completion is reported as untracked rather than as not completed.
* 📈 **Course Statistics Overview:** Single page listing all trackable activities with total accesses, unique students, engagement percentage, completed and passed counts, last access date, and section name; activities with zero unique views are highlighted; all columns are sortable.
* 📥 **Data Export:** Both the per-module and course overview statistics pages offer one-click export to **CSV** and **Excel**, covering the full dataset (not just the current page).
* 🔔 **Engagement Alerts:** Panel on the course overview that flags activities not yet viewed by any student, low-engagement activities, activities nobody has completed, activities with completion below a configurable share of the tracked students, and enrolled students with zero accesses. Only activities that actually track completion are considered for the completion alerts. Each category is consolidated into a single alert with the affected activity names shown as clickable pills — anything beyond the first five collapses behind a "show more" disclosure, so a course with dozens of matching activities stays scannable. The low-engagement and low-completion thresholds are configured separately.
* 👥 **Group-Aware:** In a course using separate groups, a teacher without `moodle/site:accessallgroups` sees totals, badges (including the completion figures and their denominator), and the per-student table scoped to their own group only — including when an individual activity overrides the course's own group mode.
* 🔢 **Site-wide Defaults:** Administrators control five independent on/off defaults — one per badge. All five default to off, so the plugin installs quietly and teachers opt in.
* ⚙️ **Display Preferences:** Each teacher overrides the site defaults via the **Configure display** button inside the Course Statistics page.
* 🔒 **Privacy-Aware:** GDPR erasure **deletes** per-student rows and transfers their view counts into aggregate columns (`deletedviews`, `deletedcount`) — no nullable user IDs in unique indexes (SQL Server compatible).
* ✅ **GDPR Compliant:** Full Privacy API implementation with data export and deletion support.
